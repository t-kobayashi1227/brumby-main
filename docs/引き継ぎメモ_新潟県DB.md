## 1. 目的と決めたこと

- brumby-poc（Supabase、新潟市のデータ）を、**新潟県全体**に広げたDBを作る。
- 作り方：小林さんの PC（Windows）のローカルの Supabase で作り、書き出して、有料プランを使う開発メンバー（Mac）に渡して取り込んでもらう。**今週中**。

- 書き出したあとに足された物件が新しいDBに入らないことは了承済み。物件の登録を止める必要はない。
- 秘密保持契約・データのライセンスは、受け取る人が開発メンバーなので問題なし。
- 画像は Storage に移さない（物件が数千件を超える、画像の枚数を増やす、表示を速くする、のどれかで移す）。
- strategy_reviews と sales_records の2列は、新しいDBにも残す。
- DB設計の見直しは後回し（「DB設計の見直し」の文書にまとめ済み）。
- 方針：今は進めて、新しいデータや詳しいデータは途中で取り入れる。

## 8. 守ること

- `CLAUDE.md` のとおり。特に：
  - APIキーは `.env.local` に置き、git に入れない。コード・ログ・画面・チャットにキーを出さない。
  - 不動産情報ライブラリAPIはアクセスログを保存する。サービス名に「不動産情報ライブラリ」を使わない。
  - 取れなかった値は「取得できず」とし、推測で埋めない。
  - エージェントの指示文（`prompts/`）を変えるときは、小林さんの了承を得る。
- brumby-poc の DB のパスワードはリセットしない（Vercel が止まるため）。
- 試し物件の値はチャットに貼らない（`lib/facts/` の注記のとおり）。
- PowerShell の注意：
  - 事実シートをファイルに書くときは `cmd /c "npm run --silent facts -- <id> > work\xxx.txt 2>&1"`（文字化けを避ける）。
  - `PGCLIENTENCODING` は設定しない（日本語のSQLで食い違う）。`\copy` には `encoding 'UTF8'` を付ける。
  - `git --no-pager diff`、`git -c core.autocrlf=false`。
